# Local h2-store checks

From MATLAB at the H2sim repository root:

```matlab
addpath(fullfile(pwd, 'tests', 'h2store'));
results = runH2StoreTests();
```

Initialize the pinned MRST submodule first, or pass that checkout to
`runH2StoreTests('/path/to/mrst')`. These tests run locally, without PHREEQC,
network access, plots or GitHub MATLAB CI. The test folder stays outside the
module runtime path. The runner restores the MATLAB path and working folder.

## Coverage

- Henry–Setschenow: zero pressure, pressure scaling, salting-out and table units.
- Hydrogen Z: zero-pressure limit and vector/scalar consistency.
- Storage schedules: consecutive equal stages, repeated cycles, final stage,
  first-well name fallback, empty and single-stage schedules.
- Frozen property values and two four-cell, two-step oil-gas simulations:
  boundary-driven injection and closed-domain pressure redistribution.
  Both use local generated SGOF tables and the local hydrogen Z correlation.
  They compare every accepted state's pressure and saturation, and check
  positive pressure and physically bounded phase fractions.

## References and limits

`reference-solutions.json` records results from the unmodified h2-store at
`e58f5a8a823dd54c0688165f1b6ecd85ce7a12f8`, before this cleanup. References
are deliberately not regenerated by the test runner. Updating them requires
reviewing the numerical change and recording its reason and provenance.
Pressure tolerances are 0.01 Pa absolute and 1e-9 relative; saturation
tolerances are 1e-9 absolute and 1e-7 relative. Property tolerances are 1e-12
relative. References detect change; they are not independent physical validation.

The original two simulations use immiscible `GenericBlackOilModel`, constant
temperature, and zero gravity. The phase-transfer tests below extend this
coverage. Hysteresis, single-phase transitions, full aquifer setups, external
pure-fluid data generation, and paper figures still need separate coverage.
In particular,
the gas-inventory formulas in `computeGasVolumes` need an accounting audit
before being accepted as reference values. These tests do not certify that
utility or the Rowe–Chou density implementation.

## Dissolution and vaporization

`H2StorePhaseTransferTest` adds three closed-domain, four-cell cases:
`disgas` alone, `vapoil` alone, and both enabled. Each runs two 10-second steps
from pressures [38, 39, 41, 42] bar and brine/gas saturations [0.8, 0.2].
Temperature is 313.15 K, NaCl molality is 1 mol/kg, and gravity is zero.
Both phases remain present; these tests do not cover phase disappearance.

Each case generates local SGOF and PVTO/PVDO/PVTG files, reads them through
MRST's Eclipse deck reader, and initializes the actual black-oil fluid model.
Pure-fluid density and viscosity inputs are synthetic; hydrogen density uses
the local Z correlation and solubility uses the local Henry correlation.
Water vapor is prescribed by a 7 kPa partial pressure, not predicted by an EOS.
For the dissolution-only case, a test-only dry-gas PVDG table completes the
deck because the local PVT writer does not emit PVDG when vaporization is off.

`phase-transfer-reference.json` freezes the initial state and every accepted
state from the merged, unmodified production code identified in its metadata.
It records pressure, saturation, Rs, Rv, dissolved gas, vaporized brine and both
component inventories. Existing immiscible references are unchanged.
The pressure and saturation tolerances match the original suite; other fields
use 1e-12 absolute and 1e-7 relative tolerances. References are never regenerated
by the runner.

Independent checks require positive pressure, two bounded phase fractions,
unit saturation sum, nonzero evolution of enabled Rs/Rv and phase-transfer
inventories, and zero values for disabled transfer paths. Closed-domain
component inventories must remain constant within 1e-10 absolute and 1e-6
relative tolerance. Inventories use pore volume, phase pressure and reciprocal
formation volume factors. In surface-volume units the two components are:

- Brine: `PV * (sO*bO + Rv*sG*bG)`.
- Hydrogen: `PV * (sG*bG + Rs*sO*bO)`.

These calculations do not call `computeGasVolumes`, whose accounting audit
remains separate. MRST currently prints an SGOF warning for oil-gas-only decks
without a separate water relative-permeability table; its zero connate-water
fallback is appropriate here. The tests do not suppress warnings globally.

## Undersaturated PVTO pressure grids

`H2StorePVTOTest` checks 1, 3 and 30 undersaturated pressure points per Rs
block. The generated deck must parse into the expected number of records,
with finite positive formation volume factors and viscosities, increasing
pressures and the expected final pressure. This covers the scalar case and
multi-record formatting in the vectorized PVTO writer. Numerical regression
references and tolerances are unchanged.

## Solubility tables

`H2StoreSolubilityTest` adds 18 checks for the water and brine generators:
scalar-reference values at 1 and 3 temperatures and 0, 1 and 3 mol/kg salt,
temperature-major row order, the smallest supported grid, pressure-count errors,
CSV pressure metadata, and reuse of an existing CSV without rewriting it.
`solubility-reference.json` contains values captured from the original scalar
implementations at the recorded source revision. In-memory comparisons use
2e-13 relative and 1e-15 absolute tolerances; cached values retain the existing
CSV precision and are checked at 6e-5 relative and 1e-12 absolute tolerance.
The original solubility correlations and CSV numeric formats are unchanged.

The generators evaluate the complete temperature-pressure grid in array
operations and write the table once. With `reCompute=false`, existing tables
can be reused without recalculating solubility. The water model ignores its
legacy `ms` option; use the brine generator for salinity. The two correlations
remain distinct, including at zero salt. Existing filename conventions are
preserved, including their misleading historical `bar` label for Pa numbers.
Use separate folders for the two models, and regenerate when changing grid
resolution because the filename does not include point counts. These tests
check numerical preservation and table handling, not independent validation
of the empirical correlations.
